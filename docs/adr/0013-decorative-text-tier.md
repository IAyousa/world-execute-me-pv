# ADR-0013: 装饰性文字层级统一（舞台指示/代码文字 dim→mid）

日期：2026-10-04 · 状态：已定稿（待导演复验 v8）
触发：导演亮度专项——"暗的不是背景，是装饰性文字，差分亮度大，
看不清细节"；并指出 typeLine 降档从**开始打字**起算（>48 字符的
长行未打完即降档）。经两轮澄清，歌词降档的最终决策（导演原话
"降档起始时间点不变，降档阈值延长1s"）：**锚点保持 t0（开始打字），
阈值 2.0/4.0 → 3.0/5.0**（亮 3s / 中 2s / 后暗档）。全片最长行
58 字符 @24cps = 2.42s < 3.0s，故"显示完才降档"对所有行自然
成立；分级设计（205/109/57）本身不变。

## 决策

层级阶梯（bg 5 / dim 57 / mid 109 / main 205 / bright 243）不变；
只修**层级使用不一致**：同为方括号舞台指示与代码表达文字，
部分落在 dim(57)、部分在 mid(109)。5 处 dim→mid：

- S03 `[ execution deferred — reason: not enough of me yet ]`
- S07 `[ execution countdown initialized ]`
- S02 `world.timeTravelForTwo("AD", 617, me, you);`
- S09 `// defined for all you ∈ world`
- S06 异常堆栈 3 行（原 2,1,1 → 统一 2）

## 明确保留 dim 的（有意为之，导演知悉）

- 伪码雨/散落字符（导演原话"不用变，现在不错"）
- B 版 `you have left` 残影行、S08 `Y O U` 幽灵字（回声效果）
- S03 中止命令的熄灭（叙事：命令被 ^C 杀死后变暗 + 红 ✗）
- 歌词 typeLine 三档降级（205→109→57，age 自打字起算）

## 勘误（同日 v9：降档对齐"唱完"）

导演进一步要求降档对齐歌词**唱完**的时刻。实现：`typeLine` 加可选
参数 `te`（唱完时刻，取自 WINDOWS 演唱窗口终点/下一句起点）——
`t < te` 全程亮档，`te` 后中档 2s，再暗档；未传 `te` 的调用维持
3.0/5.0 固定档。`brightUntil = max(te, t0+打字时长)` 保证不会在
打字完成前降档。全部 9 个场景的歌词调用已传 te（S06 用命名时刻
链 completion→youFirst→…→arguments→段末 132.5）。
验证：verse1 L0 唱句尾 t=33.0 仍亮(180)，唱完 0.6s 中档(97)、
2.6s 暗档(50)；chorus3 同过。v9 搭载。

## 教训

- 亮度问题先测分层归属再动手：观众"暗"的感知通常=某层级文字
  落在过暗档，而非全局偏暗（全片均值 5.5 但主体字 205–243）。
- 层级阶梯是设计，层级**使用不一致**是 bug——审计同类元素的实际
  ci 值（本例：同为舞台指示，一半 57 一半 109）。
