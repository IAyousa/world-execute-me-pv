# 并发分镜实现流水线（可行性判断书 · 通用模板）

> 目的：导演按变更单改分镜 → 多子代理并发实现 → 集成成片送审。
> **新会话读本文件 + [STYLE-CONTRACT.md](../STYLE-CONTRACT.md) +
> [STORYBOARD-DELTA.md](../STORYBOARD-DELTA.md) 三件套即可开工**
> （或评估本方案可行性）——三者均已随本仓库分发。占位符 `{{...}}`
> 图例见 [WORKFLOW-README.md](WORKFLOW-README.md)；"例（本项目）"为
> 本流水线首次实战（一部 3.5 分钟字符终端 PV，12 轮迭代）的真实
> 记录，保留作为各条规则的证据。

## 0. 适用前提

- 成片可拆成**按时间排序的独立"分镜单元"**，每个单元能用一个
  独立文件渲染（任意逐帧风格都行：字符画、SVG、Canvas、CSS 动画…）
- 存在权威的**时间轴锚点文件**（段落边界/歌词锚点/节拍网格），
  一切时序以它为准
- 有一位能拍板的人类导演，和两个常驻代理会话（设计、编排）

## 1. 架构依据（为什么文件级并发是安全的）

- 调度组件（例（本项目）：`src/FullPV.tsx` 的 `SCENES` 数组）按
  `{{TIMELINE_FILE}}` 的段落插拔场景，每段是独立文件
  `{{SCENE_DIR}}/Sxx*.ts`，接口统一
- N 个代理 × N 个文件 = **零合并冲突**；共享面收敛为只读文件清单
  + 集成者唯一的接线点（调度数组）
- 场景间不 import 彼此——若有跨段需求走变更单 `echo` 字段由
  编排者注入

## 2. 角色表

| 角色 | 谁 | 职责 | 上下文 |
|---|---|---|---|
| 导演 | 用户 | 填变更单、看送审 mp4、给反馈（含标注图） | 全片愿景 |
| 编排者 | 主会话 | 生成 brief、接线、门禁、一致性收口、**翻译标注图** | 全部历史 |
| 子代理 | 无状态工作单元 | 按 brief 实现单场景，过验证律后交回 | 仅 brief |

子代理每次会话无记忆——**brief 自包含性是全流水线的生命线**
（见 §4）。

## 3. 五阶段

```
P0 契约就绪     三件套 + 既有工具
P1 变更单预检   输入 = 当轮变更单（设计会话产出、导演已拍板；
                不由导演当场填单）。预检：字段完整（unit/window/
                keep/change/reject≥1/accept_anchor 带时点/echo）、
                window 与时间轴文件逐条核对、锚点时刻 ≤ 片长。
                不合格 → 问题清单原文打回设计侧，不代填不硬套；
                子代理回报"不可局部实现"同路由回设计侧改单
P2 brief 生成   编排者，每单元一份（要素见 §4，九条缺一不出工）
P3 并发实现     子代理：读契约 → 实现 → 验证律自查 → 交回
                （文件 + still ×3 + 度量输出 + 判别式自评）
P4 集成送审     编排者：接线 → 门禁（§5）→ 渲染送审版_vN.mp4
                → 反馈按单元路由回 P1
```

变更单 YAML 字段（模板）：

```yaml
unit: <ID>            # 唯一名
window: <起–止秒>     # 与时间轴文件一致
keep:                 # 不得变动的现状
  - ...
change:               # 要改什么（意图级）
  - ...
reject:               # 负面约束 ≥1（"不得如何"）
  - ...
accept_anchor:        # 带时点的验收锚（判别式：看什么、答案是什么）
  - t≈<秒>：<判别式问句>——<期望答案>
echo:                 # 跨段母题义务（首现/回收）
  - ...
notes: 实现自定项说明
```

反馈轮与实现轮同构：导演反馈 → 编排者翻译成新变更单 → 只重做
被点名的单元（其余产物直接复用）。

## 4. brief 必含要素（P2 清单，缺一不出工）

1. 单元变更单全文
2. 契约要点摘要 + 契约文档路径（令其通读）
3. 场景文件路径、段落 id、时间轴对应时刻
4. 该段现状：现版文件路径 + 1 张代表性 still 路径
5. 风格范例：定稿基准帧 + 相邻 1 段的 still（防方言化）
6. echo 注入：跨段母题在本单元的义务
7. 验证命令逐条 + 交回物清单
8. **禁止事项**重申（只读清单、一轮一意图）
9. **brief 四纪律**（实战教训，缺一出工前必查）：
   a) 只给意图 + 锚点 + 现状代码位置，**不给具体替换值**——表达式
      语义由子代理核对（例（本项目）：站4 旋钮笔误案——`t - T + 0.2`
      无括号，照抄建议值会反向推迟）
   b) 帧号一律过 `{{TOTAL_FRAMES}} − 1` 校验（例：f6354 越界案）
   c) 编排者给的测量配方先跑基线**自证有效**再进 brief（例：审计
      字符集测不到伪码雨案）；或只给工具，令子代理按目标元素自定
      并报告
   d) 变更幅度对齐最小可感知档：时间类 ≥0.5s 且配 A/B 并排物料、
      密度类 ≥40%、亮度类跨整档——低于感知档的变更导演无法验收

## 5. 集成门禁（P4，逐条过，任一失败回 P3）

```bash
node_modules/.bin/tsc --noEmit                    # 1. 零类型错误
node_modules/.bin/remotion still src/index.ts {{COMPOSITION_ID}} out/qc/U_t0.png --frame=N   # 2. 每段≥3帧
python scripts/audit_frame.py bands out/qc/U_t0.png               # 3. 间距律
python scripts/audit_frame.py bbox out/qc/U_t0.png                # 4. 尺寸律（有尺寸类变更时）
node_modules/.bin/remotion render ... out/送审版_vN.mp4            # 5. 整片
```

- **一律用本地 bin，禁 npx 调未本地安装的包**（例（本项目）：
  registry 拉取挂死）。网格断言用
  `npm run audit:grid -- <t,...> "<字符集>"`

- 门禁 2 补则（集成域单元）：调色板/公共域直改影响全片，still 验证
  须抽**受影响范围的远端段落**（调色板类 = 首/中/尾 ≥3 段各 ≥1 帧），
  巡检板必须含远端段——只验本单元会漏检全局色彩漂移
- 门禁 5 渲染范围：整片送审 `out/送审版_vN.mp4`；段落 clip 的
  帧范围**程序化生成** = 单元窗口 ∪ 全部 accept_anchor ±0.5s——
  禁止手写帧号（例：outro clip 手写范围不含尾屏锚点，导演无法
  验收该单元）
- 门禁 6（一致性巡检，编排者人工+工具）：全段抽样帧并排 board，
  判别式复核调色越界/密度节奏/留白节奏是否同方言；
  掩膜法测非调色板色像素应为 0
- 门禁 7：基线 = 本轮开工时的 HEAD（打轮次标签 `roundN-start`，
  不复用历史标签）——每单元一 commit（`U<段落>-r<轮>` 格式）；
  越界核对用 **`git diff roundN-start --stat -- <源码域>`（检查域
  限定源码域）**，全域 diff 会把基线之后的文档提交一并算入；
  **非域兜底**：`git diff roundN-start --stat -- . ':(exclude)<源码域>'
  ':(exclude)<文档域>'` 应为**空**——域外意外改动主检查里不可见，
  此行专抓；回滚 = `git checkout <tag> -- <file>`。渲染产物目录
  不入库（可由代码重渲染）

## 6. 资源与限流

- 子代理并发 3–5（Agent 工具单消息多发射）
- 渲染进程同时 ≤3（每个起 headless Chrome）；子代理内部渲 still
  必须串行
- 整片渲染分钟级：每轮集成只渲一次，中间全用 still/preview
- **验收包目录纪律**：验收目录（out/review_vN/）只放验收物料
  （clip/板/变更单），过程帧一律归档 out/qc/<轮>/_archive/

## 7. 风险与对策

| 风险 | 对策 | 出处 |
|---|---|---|
| 方言化（N 段 N 种风格） | 契约硬规则 + brief 带邻段范例帧 + 门禁巡检 | 本文 |
| 跨段连贯缺失 | 变更单 echo 字段 + brief 显式注入 | §3/§4 |
| 导演标注图被误读 | 口述为准，编排者翻译后才进 brief | §4/复核纪律 |
| 静默回退（改了没生效） | 契约防呆 + 生成脚本化 + 像素实测 | §5 |
| 子代理越界改共享文件 | 契约只读清单 + 门禁 7 逐文件核对 | 本文 |
| 尺寸/间距改了没变 | bbox/bands 像素实测 | audit_frame.py |
| 并发渲染抢资源 | §6 限流 | 本文 |

## 8. 试点先行（强烈建议）

正式轮之前，选 2–3 个代表性段落做一次全链路试点（最小验证单、
pilot_* 命名一次性件），目的：验证单段可行 + 收集"坑→条款"。
例（本项目）：首批 verse1 + chorus1 + outro 三段一轮走通、零打回、
门禁全过，结论"可行（有条件）"；试点教训驱动了本文件的多数条款。

## 11. 可选增强：视觉校验子代理（本项目 round 2 引入，导演裁定）

- **动机**：编排者会话若非原生多模态，看图经服务端中转——视觉判读
  是全体系最弱的一环；原生多模态模型判读界面帧更对口，且校验员
  未参与实现，天然造检分离
- **机制**：子代理模型参数指到视觉对口模型；校验员**只读不写、
  不渲染**——物料（stills / A-B 板 / 差异地图）由编排者备好传入；
  实现类子代理仍继承会话模型
- **输入**：该轮各单元 accept_anchor + reject 清单 + 物料路径；
  任务 = 判别式检查逐锚点 pass/fail + 证据描述
- **边界**：无终审权（报告进验收包，导演终审）；标准 = 锚点即标准，
  不引入校验员个人审美；校验员报告按假设采信，三层拦截不变
- **届时改动**：视觉相关门禁执行方式改为"校验员判读 + 编排者
  量化门禁"；本节转正并入 §5；首次触发按 §10 惯例记录实测
